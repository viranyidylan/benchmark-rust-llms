- `pub fn spawn_workers(state: AppState, shutdown: CancellationToken) -> Vec<JoinHandle<()>>`:
  spawn `state.config.worker_concurrency` tasks. Each task builds ONE `reqwest::Client`
  (`default_features=false` + rustls per Cargo.toml; `.timeout(Duration::from_secs(config.request_timeout_secs))`,
  `.redirect(reqwest::redirect::Policy::none())`) and loops:
  `tokio::select! { _ = shutdown.cancelled() => break, res = run_batch(...) => ... }` — simplest correct
  structure: loop { if shutdown.is_cancelled() { break } let jobs = db.claim_due_jobs(8).await; if jobs.is_empty()
  { tokio::select! { _ = shutdown.cancelled() => break, _ = sleep(poll_ms) => {} } continue; }
  for job in jobs { handle_one(&client, &state, &job).await; } } — sequential-per-task is fine.
- `async fn handle_one(client, state, job)`: call `deliver`; on Ok → `db.mark_delivered(job.id)`;
  on Err(e): if `job.attempts >= job.max_attempts` → `db.mark_dead(job.id, &e.to_string())` (DLQ);
  else `db.reschedule_job(job.id, Utc::now() + backoff(job.attempts, base_ms, max_ms), &e.to_string())`.
  Note: attempts was already incremented by claim_due_jobs, so job.attempts is the attempt just made.
- `fn backoff(attempts: i64, base_ms: u64, max_ms: u64) -> Duration`:
  `base * 2^(attempts-1)` (saturating, cap the shift at ~20 to avoid overflow), cap at max_ms, then apply
  ±20% jitter with `fastrand`: `let j = fastrand::f64() * 0.4 - 0.2; ms = ms * (1.0 + j)`.
- `async fn deliver(client: &reqwest::Client, job: &Job, config: &Config) -> Result<(), DeliveryError>`
  (DeliveryError: thiserror enum with `Http(u16)` and `Transport(String)`): POST `job.destination` with
  body = compact-serialized `job.payload`, headers `content-type: application/json`,
  `x-webhook-id: <uuid>`, `x-webhook-signature: <security::sign_body(&config.hmac_secret, body_bytes)>`.
  2xx → Ok(()); other status → Err(Http(status)); request error/timeout → Err(Transport).
- tracing: `info!` on delivered (id, destination, attempts), `warn!` on retry (id, attempt, error,
  next delay), `error!` on dead-letter (id, attempts, error). NEVER log payload bodies or the HMAC secret.
